# Project Rules

## Release Tooling & Pull Requests
- We use **Release Please** for automated versioning and release management in this repository. Ensure commit messages and PR headers follow Conventional Commits (e.g. `chore:`, `feat:`, `fix:`) appropriately so Release Please can accurately manage library version bumps and changelogs without triggering unintended releases for demo or sample app changes.
- **Draft PRs**: All pull requests are to be created and uploaded as **drafts** (e.g., `gh pr create --draft`) until authorization is explicitly given by the user to mark them ready for review.

## Java & Kotlin Target Versioning
- **DO NOT upgrade the Java/bytecode target to Java 17 until explicitly given the all-clear.**
- Keep published library modules targeting **Java 11** (`JavaVersion.VERSION_11`, `JvmTarget.JVM_11`) to prevent breaking changes for downstream consumers on AGP < 8.0 and Java 11 toolchains (avoiding Kotlin inlining failures: `Cannot inline bytecode built with JVM target 17 into bytecode that is being built with JVM target 11`).

## Test Coverage & History
- Coverage is tracked over time. After every merge to `main`, the `Record coverage history` workflow appends a row per module per suite to `history.csv` and regenerates `COVERAGE.md`, both of which live on the [`coverage-history`](../../tree/coverage-history) branch. They are generated by `.github/scripts/coverage_history.py`. Never edit them by hand.
- The data is kept off `main` deliberately. Branch protection on `main` uses strict required status checks, so any commit pushed there marks every open pull request out-of-date and forces contributors to update their branch and re-run CI. Keeping coverage data on its own branch means recording it costs contributors nothing.
- Two suites are recorded separately:
  - `unit`: JVM tests run by `./gradlew koverXmlReportDebug`, covering the three published library modules (`robolectric-testing`, `golden-testing`, `visual-testing`).
  - `instrumentation`: Emulator tests run by `./gradlew connectedAndroidTest`, covering the modules that own `androidTest` sources.
